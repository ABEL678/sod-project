# СОД Stream-CAD — Волна 3 «Продуктовый характер»

Реализация раздела 9.3 роадмапа «Аудита 2.0». Волна закрывает четыре
стратегических пункта: workflow зон ISO 19650, уведомления и экран
«Мои замечания», кластеризация маркеров и секции карточки замечания,
командная палитра и PWA.

**Объём:** 30 файлов (18 изменено, 12 новых), +2 589 / −187 строк,
1 миграция (0006_notification). Тесты: **284/284 OK**, `manage.py check`
без замечаний. Ограничения команды соблюдены: без React/SPA, без
Storybook, Django + HTMX + vanilla JS.

---

## 1. Что внутри

### 1.1. Сегмент-контрол зон ISO 19650 и workflow-действия

Главный стратегический пункт аудита. На странице проекта — сегмент-контрол
«Все зоны / В работе / На согласовании / Опубликовано / Архив» со счётчиками
документов; в таблице — колонка «Зона» и колонка «Действия».

Переходы выполняются кнопками в документе и идут по матрице ролей
(в отличие от свободного переноса папкой, поток соответствует ISO 19650):

| Действие | Переход | Кто может |
|---|---|---|
| Подать на согласование | WIP → Согласование | admin, ГИП, разработчик, подрядчик (в своём разделе) |
| Вернуть в работу | Согласование → WIP | admin, ГИП, проверяющий, нормоконтроль |
| Опубликовать | Согласование → Публикация | admin, ГИП |
| В архив | Публикация → Архив | admin, ГИП |

Документ переносится в каноническую папку-зону (пересоздаётся, если её
снесли), статус документа синхронизируется с зоной, участники получают
уведомления.

**Файлы:** `storage/domain/services.py` (ZONE_WORKFLOW_ACTIONS,
transition_document_zone, get_zone_counts), `storage/adapters/views.py`
(DocumentWorkflowView, zone-фильтр), `storage/adapters/urls.py`,
`storage/adapters/tables.py`, шаблоны `_documents_panel.html`,
`document_detail.html`, `redesign.css`.

### 1.2. Уведомления и экран «Мои замечания»

- Модель `issues.Notification` + миграция `0006`; сервис `issues/notify.py`
  — единая точка создания (инициатор своих действий не получает).
- Колокольчик в топбаре со счётчиком непрочитанных: список подгружается
  лениво через HTMX при открытии, кнопка «Прочитать всё».
- Контекст-процессор `notifications_badges` — два COUNT-запроса на страницу.
- Экран `/my-issues/`: дайджест-чипы «Все мои 9 · На вас N · Вы автор N ·
  Скоро срок N · Просрочено N», фильтры assigned/created/open/overdue,
  поиск, живые дедлайн-бейджи из Спринта 1.

**Файлы:** `issues/models.py`, `issues/notify.py`, `issues/views.py`,
`issues/urls.py`, `issues/context_processors.py`, `issues/migrations/0006_notification.py`,
`my_issues.html`, `_notifications_list.html`, `_topbar.html`, `sod_core/settings.py`,
`viewer.css` (стили колокольчика).

### 1.3. Кластеризация маркеров и секции карточки замечания

- Пины вьювера, центры которых ближе 28 px на экране, сворачиваются в
  один бейдж с количеством и цветом доминирующего статуса; клик —
  приблизить к группе, повторный — раскрыть список замечаний группы.
- Карточка замечания перестроена из плоского списка в секции
  «Суть → Ответ → Реквизиты → Статус → Переписка» (складные секции).

**Файлы:** `static/js/pdf_viewer.js` (clusterMarkers, drawClusterBadge),
`issues/templates/issues/_card.html`, `viewer.css`.

### 1.4. Командная палитра и PWA

- **Ctrl+K / Cmd+K** — палитра поиска по проектам, документам и замечаниям,
  доступным пользователю (`GET /palette/?q=…`), навигация стрелками,
  Enter — переход. Дебаунс 180 мс, минимум 2 символа.
- **PWA:** `manifest.webmanifest` (standalone, иконки 192/512 + maskable),
  service worker `/sw.js` (свой Django-view — scope «/»): навигация —
  network-first, статика — stale-while-revalidate; API, POST и всё
  с query-параметрами не кэшируется.

**Файлы:** `static/js/palette.js`, `_palette.html`, `static/js/sw.js`,
`static/manifest.webmanifest`, `static/icons/*`, `storage/adapters/views.py`
(PaletteSearchView, ServiceWorkerView), `base.html`.

## 2. Попутно исправленный дефект

`.topbar { overflow: hidden }` (правило «A21: one-line topbar») клиппил
дропдаун колокольчика по границе шапки — меню было видно на ~10 px.
Заменено на `overflow: visible`; однострочность шапки обеспечивают
`flex-wrap: nowrap` и собственные `overflow: hidden` у детей
(.topbar-left, .crumb, форма поиска, водяной знак).

## 3. Установка

Патч применяется из корня репозитория **на состояние после Спринта 2**
(последний локальный коммит `7e784eb` либо применённый `sod_sprint2.patch`):

```bash
git apply --check sod_wave3.patch   # проверка
git apply sod_wave3.patch           # применение
python manage.py migrate            # 0006_notification
python manage.py test               # 284 теста
python manage.py runserver
```

Альтернатива без git — скопировать содержимое папки `файлы/` поверх
проекта (структура соответствует корню репозитория).

Кумулятивный патч `sod_sprint1+2+3_cumulative.patch` переводит исходный
репозиторий (до всех спринтов) сразу в состояние Волны 3.

## 4. Проверка после установки

1. Проект → сегмент-контрол зон со счётчиками; кнопка в строке документа
   показывает число доступных workflow-действий.
2. Документ → «Подать на согласование»: документ уезжает в зону
   «Согласование», ГИПам падает уведомление в колокольчик.
3. ГИП → «Опубликовать»; автору и загрузчику версии — уведомление.
4. `/my-issues/` — дайджест, фильтры, просрочка.
5. Вьювер → пины в одном месте свёрнуты в бейдж с числом; клик — зум.
6. Ctrl+K → «АР» — палитра находит документ и замечания.
7. DevTools → Application → Manifest: манифест и service worker активны.

## 6. Известные ограничения

- PWA-офлайн рассчитан на статику и оболочку; первичная загрузка PDF
  документа требует сети (осознанно: чертежи не кэшируем).
- Уведомления внутренние (без e-mail) — канал почты не входит в Волну 3.
- Кластеризация работает на текущем листе одностороннего рендера.
