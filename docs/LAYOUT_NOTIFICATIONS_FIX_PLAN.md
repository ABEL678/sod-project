Локальные заплатки (sticky-правила, inline-скрипты) только маскируют это — поэтому кодеры «лечат симптомы».

### 2.2. Проблема 1: почему «уезжает верх» и почему ломались sticky-попытки

**Вкладки «Задания» и «Запросы» — эталон (работает):**
- tasks: `.toolbar` — прямой ребёнок `.ai-tabpane`, список — внутри `.ai-tabpane__scroll` (`project_detail.html:500-659`).
- rfi: `_rfi_tab.html` сам содержит `.toolbar` → фильтры → `.ai-tabpane__scroll` (`_rfi_tab.html:6-31`, скролл-контейнер `:32`) — при включении в панель тулбар закреплён.

**Три ИИ-вкладки — сломаны (симптом «уезжает»):**
- `project_detail.html:486-489` — `{% elif active_tab == 'ai-search' %}<div class="ai-tabpane__scroll">{% include 'ai_checks/_rag.html' %}</div>`: обёртка-скролл обнимает **весь** инклуд.
- `:490-493` (ai-report) и `:494-497` (ai-kb) — то же самое.
- А внутри инклудов первым элементом идёт `.toolbar` («Поиск по документам…» — `_rag.html:10-14`; «Отчёты по подтверждённым замечаниям» — `_report.html:6-11`; «База знаний: …» — `_kb.html:10-16`) и далее фильтровые формы (`_rag.html:16+`, `_report.html:14+`) — всё это **внутри** скролл-контейнера → при прокрутке заголовок и фильтры уезжают наверх вместе с контентом. Это и есть reported bug; никакой «сломанной sticky» в текущем CSS нет.

**Участники / Корзина — третий вариант анатомии (скролла нет вообще):**
- participants: `.toolbar` + `.participants-wrap` прямо в `.ai-tabpane` без скролл-обёртки (`project_detail.html:333-392`); `.ai-tabpane { overflow: hidden }` → длинный список участников обрезается без возможности доскроллить.
- trash: то же (`:393-483`).
- issues: `_issues_panel.html` — корень `#issuesPanel`, внутри сводка-карточки + таблица; в панель включается целиком (`project_detail.html:662-663`), скролл-анатомии не имеет.

**Почему sticky-попытки кодеров ломали прокрутку (для истории):**
1. Sticky внутри `.ai-tabpane__scroll` на элементе, чей родитель — сам скролл-контейнер, «прилипает» к его верхней кромке — но без переноса `.toolbar` наружу контента остаётся двойной эффект: sticky-заголовок перекрывает первые строки контента (`top: 0` без компенсации высоты), и часть контента оказывается «под шапкой» недостижимой — ровно тот симптом, что описан в задаче.
2. Sticky на элементах вне скролл-контейнера прилипает к window — а так как `.app-main { overflow: visible }` (app.css:595), на десктопе возможен body-скролл при переполнении → заголовок уезжает под топбар. Плюс sticky-элементам задавали смещение от топбара/вкладок, которое не совпадало с реальной высотой соседей — контент прятался под прилипшим тулбаром.
3. Откат (d176eab, «rollback broken sticky headers») снял sticky-правила, но оставил хвосты: класс `.app-tabs-wrap--no-grow { flex: 0 0 auto; height: auto; }` (app.css:690) + условная модификация `#mainTabs` в шаблоне (`project_detail.html:226`) и удаление `overflow: visible` у `.toolbar` — точечные заплатки, не меняющие анатомию.

### 2.3. Проблема 2: механика дублирования блока «Документы»

Проверенная цепочка:

1. `ProjectDetailView` **всегда рендерит полную страницу**: `template_name = 'storage/project_detail.html'` (`storage/adapters/views.py:571,577`), HTMX-веток в `get()` нет (частичные ответы делают только карточки заданий — `views.py:2485+`, другой класс).
2. ИИ-вкладки переключаются через HTMX: `hx-get="?tab=ai-kb" hx-target="#mainTabs" hx-select="#mainTabs" hx-swap="outerHTML show:window:top"` (`project_detail.html:308-317`, KB-якорь).
3. `#documentsPanel` — **вне** `#mainTabs` (`project_detail.html:670-676`, отдельный `{% if active_tab == 'documents' %}` после закрытия `#mainTabs` в `:667`).
4. Переход «Документы» → «База знаний»: HTMX вырезает `#mainTabs` из ответа и заменяет им текущий `#mainTabs` (внутри которого теперь KB-панель), но `#documentsPanel` в DOM **не трогается** — он остаётся под новой панелью. Итог: «База знаний» + внизу блок «Документы» (таблица, фильтры, папки).
5. Обратный переход «База знаний» → «Документы» — обычная ссылка (полная перезагрузка, `project_detail.html:226-233`) — дублирования нет. Поэтому баг «односторонний» и проявляется выборочно: он возникает только когда стартовой вкладкой были «Документы», а ИИ-вкладку открыли через HTMX. «Иногда на Отчётах» — тот же сценарий.

Серверная изоляция при этом корректна: все панели — взаимоисключающие ветки `{% if/elif %}` (`project_detail.html:331-664`), и на `?tab=ai-kb` сервер рендерит только KB-контент. Дублирует не сервер — **DOM после свопа**. Именно поэтому проверка кодеров `{% if active_tab == '...' %}` ничего не дала: они проверяли не то место.

## 3. Решение

### 3.1. Единая анатомия вкладки (фикс проблем 1 и 2 одновременно)

Целевая структура — одна для всех восьми вкладок, без исключений и модификаторов:

```
#mainTabs.app-tabs-wrap                                  ← единственная цель hx-свопа
├─ nav.app-tabs                                          ← закреплена всегда
└─ #mainTabContent.ai-tabpane                            ← рендерится ВСЕГДА (в т.ч. documents)
   ├─ .toolbar            (опц.: вторая строка фильтров) ← закреплена (снаружи скролла)
   └─ .ai-tabpane__scroll                                ← скроллится только это
      └─ контент вкладки (таблица/карточки/формы)
```

Свойства анатомии:
- `.app-tabs-wrap` сохраняет `flex: 1 1 auto; min-height: 0` (app.css:659-665) — модификатор `--no-grow` удаляется вместе со случаем «documents особенный».
- `.ai-tabpane` сохраняет `overflow: hidden` (app.css:676) — переполнение физически невозможно мимо скролл-обёртки.
- `.toolbar` — `flex: 0 0 auto` вне скролла — фиксирован по определению; sticky не используется вовсе (внутритабличные sticky-заголовки `thead` сохраняются — они легитимны внутри своих скролл-обёрток).

### 3.2. Уведомления: ленивый список + «прочитано» без гонки

Принцип: **клик = одно действие без побочных гонок**: (1) немедленно обновить UI оптимистично; (2) отправить POST так, чтобы он пережил выгрузку страницы; (3) перейти по ссылке после ответа (или по таймеру-fallback). Плюс вернуть ленивую загрузку списка (факт открытия дропдауна = свежие данные).

Сервер дополняется точным счётчиком в ответе, чтобы клиент не «угадывал» декрементом.

### 3.3. Соответствие спеке 4.1

`allowed_tabs` возвращается к менеджерскому гейту для ИИ-вкладок (шаг 0 ниже).

## 7. Граничные случаи

- **`?tab=` мусорный** → не совпадает ни с одной веткой → пустая `.ai-tabpane`. С шагом 0 для ИИ-вкладок и существующим whitelist `allowed_tabs` остальные вкладки безопасны; для недопустимых значений вьюха уже рендерит дефолт (`views.py:852-855`). Дополнительно: ветка `{% else %}` в цепочке панелей не требуется — пустая панель визуально эквивалентна «Документам не выбрано», но допускается добавить `{% else %}`-ветку с заглушкой (опционально).
- **Уведомление, чей документ удалён** (`document__is_deleted` в счётчиках не фильтруется) — переход по url может дать 404: допустимо (замечание вне скоупа; фильтрация — отдельная задача, не в этом плане).
- **Открытый дропдаун при переключении вкладок через HTMX** — дропдаун закрывается Bootstrap-ом сам; список перезагружается при следующем открытии (ленивая схема) — несвежих данных не остаётся.
- **Несколько вкладок браузера** — оптимистичное «прочитано» в одной вкладке не синхронизирует другую: счётчик той вкладки обновится при её следующей полной перезагрузке. Допустимо (как и сейчас).
- **Мобильные** (`@media` app.css:1640+): анатомия панели та же, `.ai-tabpane__scroll` остаётся скролл-узлом; проверить тач-скролл на iOS (`-webkit-overflow-scrolling: touch` уже применяется к `.doc-table-wrap` в `:1717-1721` — при необходимости перенести на `__scroll`).
- **Печать/офлайн-PWA** — не в скоупе; `/help/` и SW-bypass не затрагиваются.

## 8. Что сознательно не делаем

1. **Не возвращаем sticky-правила для тулбаров/вкладок** — при единой анатомии они не нужны; sticky остаётся только внутри скролл-обёрток таблиц (`thead`, `.table-pagination`) — там он корректен.
2. **Не переводим ИИ-вкладки на полную перезагрузку** (вариант «убрать hx-*» отвергнут): HTMX-своп после L1 корректен, терять SPA-отзывчивость не нужно.
3. **Не трогаем серверную изоляцию панелей** — `{% if/elif %}` корректны; проблема была только в DOM-свайпе.
4. **Не переносим список уведомлений в БД-состояние дропдауна** («открыл = всё прочитано») — требование задачи: пометка **по клику на элемент**; bulk-кнопка «Прочитать всё» уже есть.
5. **Не меняем `Notification`/модель, вербы, создание уведомлений** — только отображение и пометка чтения.
6. **Не добавляем WebSocket/поллинг для живого счётчика** — вне скоупа.
7. **Не рефакторим `.app-main { overflow: visible }` на десктопе** — после L1 переполнение возможно только из `flash-stack` (absolute) — это не скролл-контент.
