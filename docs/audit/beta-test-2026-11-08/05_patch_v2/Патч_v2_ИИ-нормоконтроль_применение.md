## Состав патча по блокам

### Блок 1 — SPDS.STAMP/RAME: ложные срабатывания
Файлы: `ai_checks/pdfium_tools.py`, `ai_checks/domain/rules.py`.
- `page.rect` заменён на **`page.mu_rect`** — новый MU-прямоугольник страницы
  (MediaBox/CropBox в неповёрнутой TL-системе геометрии `iter_*`/`get_text`).
  Примечание: `page.mediabox` в pdfium-обёртке — BL-система с абсолютными
  координатами, поэтому правила используют `mu_rect` (эквивалент mediabox в
  MU-координатах); для листов с нулевым началом размеры совпадают с MediaBox.
- Зона штампа считается в долях **отображаемого** листа с пересчётом в MU
  (`_displayed_zone_to_mu`) — при /Rotate 90/180/270 угол больше не уезжает.
- Fallback по заданию: если path-геометрия штамп не подтверждает —
  **`iter_text_runs()`** ищет метки `STAMP_LABELS` в зоне (±5% допуска).
- Дополнительно (из диагностики GigaCode «штамп может быть растровым»):
  растровый fallback (`iter_images`, покрытие зоны ≥80%) и структурный
  fallback (`iter_object_bounds` — объекты, целиком лежащие в зоне ≥6;
  лист 4 файла 4400_ОВ — весь чертёж из 14 447 shading-объектов).
- Форма 3 титульных листов (штамп слева-внизу): второй шанс по текстовым
  меткам; в `STAMP_LABELS` добавлены «кол.уч», «№док», «подп.».
- `check_frame`: та же MU-зона + fail-open, если path-геометрия выходит за
  MediaBox (клип-экспорт: линия 9331 pt при листе 1191 pt — лист 3 4400_ОВ).
- **Результат на реальном файле с прода:** 16 ложных находок → **0** штамповых
  и 4 → 1 рамочных (лист 7, спецификация — рамка на глаз есть, но один край
  невидим для path-API; единственная остаточная находка).

### Блок 2 — нормативная база СПДС
Файлы: `ai_checks/domain/models.py`, миграции, `views.py`, `_finding_row.html`.
- `RuleDefinition.norm_ref` — полное обоснование («ГОСТ 21.613-2014, п. 5.2»),
  показывается в строке находки.
- **Миграция 0012** (сид, idempotent): norm_ref для трёх базовых правил
  (ГОСТ Р 21.101-2026) + 18 заглушек дисциплинарных стандартов
  (`DISC.*`, `is_active=False`, коды не в `RULE_CHECKS` — движком не
  исполняются): электроика 21.613/21.607/21.608, газ 21.609/21.610,
  автоматизация 21.408, конструкции 21.501/21.502/21.504, дороги 21.701/
  21.702/21.207, изыскания 21.301/21.709, общие 21.110/21.201/21.002/21.114.
- Селектор «Проверка по»: базовый ГОСТ Р 21.101-2026 + внутренние стандарты
  проекта (`InternalDocument.doc_type='internal_standard'`, та же
  видимость, что у блока БЗ).

### Блок 3 — управление проверкой
Файлы: `_panel.html`, `panel.html`, `_start_controls.html` (новый),
`views.py`, `tasks.py`, `services.py`, `pdf_viewer.js`.
- FAB переименован: «Проверить» → **«ИИ-нормоконтроль (СПДС)»**; текстовая
  кнопка «Закрыть» в панели (дублирует крестик, `[data-ai-close]`).
- Кнопки **«Проверить лист»** (page_number из вьювера через
  `window.PdfViewerGetCurrentPage` — новый геттер в `pdf_viewer.js`) и

- `run_rules_check(..., page_number=None, norm_source_id=None)`; задача
  Celery и вьюха `start_check` принимают и валидируют оба параметра
  (лист вне диапазона → полный прогон; чужой/несуществующий стандарт → базовый).
- `CheckRun.page_number / norm_source / norm_source_label`; в панели находки
  фильтруются по листу прогона («показано N из M» + кнопка «Проверить всё»).

### Блок 4 — эмбеддинги bge-m3
Файлы: `ai_checks/adapters/embedding_onnx.py`, `requirements.txt`.
- Реальный ONNX-инференс bge-m3: onnxruntime CPU, токенизатор transformers,
  dense 1024, CLS-pooling + L2-нормализация, max_length 512.
- Модель ожидается в `settings.AI_EMBEDDING_MODEL_DIR` (по умолчанию
  `<BASE_DIR>/ml_models/bge-m3`: `model.onnx` + файлы токенизатора HuggingFace,
  экспорт BAAI/bge-m3). Пока файлов нет — прежняя SHA-256 заглушка с warning;
  `model_version` честно различает `bge-m3-stub-v1` / `bge-m3-onnx-v1`.
- **Важно:** после скачивания модели нужна переиндексация («Переиндексировать
  проект») — векторы заглушки и bge-m3 несравнимы.

### Блок 5 — шрифт с кириллицей в PDF
Файлы: `ai_checks/domain/services.py` (`_register_cyrillic_font`).
- Регистрируется TTF с кириллицей: ищет `static/fonts/GolosText(-Regular|-Bold).ttf`,
  `static/fonts/DejaVuSans(.ttf|-Bold.ttf)`, системный
  `/usr/share/fonts/truetype/dejavu/DejaVuSans*.ttf`; если ничего нет —
  прежний STSong-Light (экспорт не падает до добавления шрифта).
- **Действие владельца:** положить TTF в `static/fonts/` (GolosText
  предпочтительнее). Проверено: с системным DejaVu шрифт встраивается в PDF
  (`AAAAAA+DejaVuSans`, emb=yes).

### Блок 6 — отчёт ГИПу (красивый формат)
Файлы: `ai_checks/domain/services.py` (`gip_report_pdf`, `gip_report_docx`,
`_report_document_breakdown`, `_report_rows` +7 колонок).
- PDF переехал на **platypus** (таблицы, стили, номера страниц): титульный
  блок → краткое резюме (LLM) → статистика (по статусам + по ответственным) →
  детализация по документам → ключевые проблемы (топ-10, было 7) → выводы и
  рекомендации → приложение (полный список замечаний с листом и текстом).
- Word (python-docx) — та же структура.
- Обновлены 3 теста под новый UI/версии (`test_views`, `test_indexing`,
  `test_reports`).

## Зависимости и миграции

- **Новая зависимость:** `transformers>=4.51,<6` (requirements.txt;
  `onnxruntime` уже был). Устанавливается с `tokenizers` автоматически.
- **Миграции: `0011` (схема: norm_ref, CheckRun.page_number/norm_source),
  `0012` (сид стандартов).** Применяются независимо от AI_CHECKS_ENABLED.
- Для блоков 4–5 нужны артефакты развёртывания: модель bge-m3 в
  `ml_models/bge-m3`, TTF-шрифт в `static/fonts/` (без них — рабочий
  fallback: заглушка SHA-256 и STSong-Light).
