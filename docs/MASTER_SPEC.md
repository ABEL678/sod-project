# MASTER_SPEC.md — СОД для проектной компании

**Версия:** 1.3
**Дата:** 2026-10-29
**Статус:** Живой документ.

## 1. Цель продукта

Дать проектной компании (25 человек) порядок в файлах: актуальные версии, понятные права, быстрый поиск. Интеграция с экосистемой (ГИП-Ассистент, ВОР-билдер, Витро-трекер). Возможность продавать как SaaS (stream-cad.ru), так и On-premise (коробка).

## 2. Пользователи и роли

| Роль | Что делает | Что видит |
|---|---|---|
| **Platform Owner (суперюзер)** | Управляет компаниями, назначает админов | Список компаний. Проекты — только если компания не приватная. |
| **Администратор компании** | Управляет пользователями, проектами, правами | Всё в своей компании |
| **ГИП** | Ведет проект, утверждает документы, ставит замечания | Всё в своих проектах |
| **Инженер** | Загружает чертежи в свои разделы, читает смежные | Свои разделы — запись, остальные — чтение |
| **Наблюдатель** | Смотрит, не меняет | Только чтение |
| **Смежник (contractor)** | Читает выданные разделы, загружает свои | Только разрешенные разделы |

## 3. Функциональные требования (по этапам)

### Этап 1-7. Ядро, ведомости, замечания, поиск, GUI (ЗАВЕРШЕНЫ)
(Краткое описание пройденных этапов).

### Этап 7.5. Файловая структура и выпуск комплектов (T8-CORE — В РАБОТЕ)
**Цель:** полноценная среда для проектировщиков.
- Иерархия папок (Folder).
- Кнопки создания проекта/раздела/папки.
- Ссылки (public_link_token).
- Массовые действия (ZIP, перемещение).
- Корзина (Trash).
- Статусы жизненного цикла (WIP, SHARED, PUBLISHED, ARCHIVED).

### Этап 8. PDF-вьюер и визуальные замечания (пин) — СЛЕДУЮЩИЙ
- PDF.js на странице версии.
- Создание замечания кликом по PDF (page_number, x_ratio, y_ratio).

### Этап 9. Карточка замечания 2.0
- IssueComment, IssueAttachment.
- assignee, due_date.
- «Мои замечания», экспорт в Excel.

### Этап 10. Экспорт PDF с наложенными замечаниями (PyMuPDF).

### Этап 11. Интеграция с экосистемой (API Gateway).

### Этап 12. UI Consistency (Приведение всех страниц к единому стилю).
- Стартовая страница (список проектов/компаний).
- Страница документа (история версий + замечания).
- Страница поиска.

### Этап 14. Мультитенантность и управление компаниями (T14)
**Цель:** продажа СОД нескольким компаниям (SaaS + On-premise).
- Модель Company: поле `is_private`.
- Сервисы: `get_all_companies`, `create_company`, `assign_company_admin`.
- UI для суперюзера: список компаний, создание, impersonation.
- UI для админа компании: создание проектов.
- **Критерий готовности:** суперюзер видит компании, приватная компания скрывает проекты.

## 4. Нефункциональные требования
(Без изменений: 25 человек, 500 ГБ, <1 сек отклик, ежедневный бэкап).

## 5. Ограничения и допущения
- Не делаем мобильное приложение, интеграцию с CAD на старте.
- Не делаем микросервисы, Celery, Redis, pgvector.
- Не делаем тонкие права на уровне отдельных документов.

## 6. Порядок работ и контрольные точки

| Этап | Что делаем | Контрольная точка |
|---|---|---|
| 1-7 | Ядро, поиск, GUI | Готово |
| 7.5 | T8-CORE (папки, ссылки, корзина) | Проектировщик создает папки и копирует ссылки |
| 8 | PDF-вьюер и пины | Замечание видно на PDF |
| 9 | Карточка замечания 2.0 | Обсуждение и сроки работают |
| 10 | Экспорт PDF с замечаниями | PDF с пинами скачивается |
| 11 | API Gateway | ВОР-билдер забирает СО через API |
| 12 | UI Consistency | Все страницы в едином стиле |
| 14 | Мультитенантность (T14) | Приватная компания скрывает проекты |
