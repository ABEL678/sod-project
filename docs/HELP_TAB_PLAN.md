## 1. Резюме (TL;DR)

| Требование задачи | Решение |
|---|---|
| 1. Название и место | Кнопка-иконка `bi-question-circle` + подпись «Помощь» в топбаре (`_topbar.html`), рядом с кнопкой обратной связи (bug). Открывает страницу `/help/` (новое приложение Django `help`) |
| 2. Источник контента | Markdown-файлы `docs/help/*.md` с YAML-шапкой (slug, title, section, order, keywords, updated). Рендер — `markdown-it-py` (новая зависимость, единственная). Кэш в процессе с инвалидацией по mtime |
| 3. UI | Двухколоночная страница: слева дерево статей по разделам (TOC), справа статья. Сверху строка поиска: HTMX-вьюха `help:search` отдаёт частичный шаблон с совпадениями и подсветкой `<mark>` |
| 4. Контекстность | Карта «URL → статья» в единственном источнике `help/context_map.py` (url_name + GET `tab` → slug). Темплейт-тег `{% help_context_url %}` строит ссылку кнопки «?» под текущую вкладку (с «Заданий» → `/help/tasks/`, с «Матрицы заданий» → `/help/tasks-matrix/`, с «Документов» → `/help/documents/`). Все slug карты проверяются тестом |
| 5. Обращение | Повторное использование контура обратной связи 2B: модель `Feedback` (не `Issue` — он жёстко привязан к документу), новая категория `QUESTION` «Вопрос», кнопка «Не нашёл ответ? Создать обращение» внизу статьи открывает существующую модалку `#feedbackModal` с префиллом (JS `help.js`). Админ видит тикет в `/feedback/` |
| 6. AI-поиск (опция) | Этап H5, за гейтом `AI_CHECKS_ENABLED`: чанки статей справки → `EmbeddingService` (bge-m3) → in-memory косинусный индекс (без БД/миграций) → `LLMProvider` с ответом строго по корпусу справки и ссылками на статьи. Кнопка «Спросить у ИИ» появляется, когда обычный поиск дал 0 результатов |

Ключевые принципы: **(а)** контент — файлы в репозитории (никаких моделей и миграций для статей); **(б)** один источник правды для контекстности — код, а не поля в шапках статей; **(в)** обращение из справки — это та же модалка и та же таблица `/feedback/`, что уже есть, а не второй контур тикетов.

### 4.2. Маршруты (`help/urls.py`)

| Маршрут | Имя | Вьюха | Назначение |
|---|---|---|---|
| `help/` | `help:home` | `HelpHomeView` (RedirectView) | Редирект на `help:article` со slug `start` (или `?to=<slug>`) |
| `help/search/` | `help:search` | `HelpSearchView` | GET `?q=`; HTMX → партиал `_search_results.html`; без `HX-Request` — полная статья-обёртка (деградация без JS) |

### 4.3. Загрузчик контента `help/content.py`

Единственная содержательная бизнес-единица — по правилу проекта логика живёт в модуле уровня сервиса (аналог `storage/domain/services.py`), вьюхи тонкие.

```python
@dataclass(frozen=True)
class Article:
    slug: str
    title: str
    section: str          # имя раздела для дерева TOC («Замечания», «ИИ», …)
    order: int            # порядок внутри раздела и общий порядок сортировки
    keywords: list[str]   # доп. слова поиска
    updated: str          # дата из шапки — показывается в подвале статьи
    html: str             # отрендеренный markdown
    plain_text: str       # текст без разметки — корпус поиска
    headings: list[tuple[str, str]]   # [(anchor_id, текст)] — оглавление статьи
```

Функции:

| Функция | Контракт |
|---|---|
| `load_articles(force: bool = False) -> dict[str, Article]` | Глобб `HELP_CONTENT_DIR/*.md`, парсинг шапки (PyYAML) и тела (markdown-it-py, **html=False** — сырой HTML в md экранируется). Кэш в процессе с инвалидацией по сумме mtime файлов; `force=True` при `settings.DEBUG`. Ошибки: нет slug/title → файл пропускается с `logger.warning` (страница не падает); дубликат slug → старший по mtime выигрывает, дубль пропускается; пустой каталог → пустой dict + warning |
| `get_article(slug) -> Article \| None` | Обёртка над `load_articles()` |
| `toc_tree(articles) -> list[Section]` | Группировка по `section`, сортировка по `order`; используется в `_toc.html` и в контексте `HelpArticleView` |

Формат статьи (контракт шапки — фиксируем в плане, Кодер делает по нему стартовые файлы):

```markdown
---
slug: issues
title: Замечания
section: Замечания
order: 30
keywords: [пин, статус, экспорт, блокировка]
updated: 2026-11-18
---
# Замечания

## Что это
Текст статьи… Ссылка на подзаголовок другой статьи: [пины на PDF](viewer/#пины).
```

### 4.4. Вьюхи `help/views.py`

| Вьюха | Логика |
|---|---|
| `HelpHomeView(LoginRequiredMixin, RedirectView)` | `get_redirect_url()`: `?to=<slug>` при валидном slug, иначе `resolve_context_slug(...)` от реферера не делаем (ненадёжен) — просто `start` |
| `HelpArticleView(LoginRequiredMixin, View)` | `slug` из URL → `get_article()`; 404 если нет. Контекст: `article`, `sections` (дерево), `current_section`, `prev`/`next` (соседи по общему `order` — навигация «← →» в подвале), `breadcrumbs` («Помощь / Раздел / Статья») |
| `HelpSearchView(LoginRequiredMixin, View)` | `q = request.GET.get('q','')`; при `len(q.strip()) < 2` — пустой результат с подсказкой. `search_articles(q)` → контекст `_search_results.html`. При `HX-Request` — чистый партиал (HTTP 200, `HX-Push-Url` не нужен), иначе рендер полной страницы с партиалом внутри (без JS поиск остаётся рабочим) |

Все вьюхи под `LoginRequiredMixin` — весь интранет-контур проекта закрыт логином, отдельных прав не требуется (читать справку может любой сотрудник).

### 6.2. Темплейт-тег

`help/templatetags/help_tags.py`:

```python
@register.simple_tag(takes_context=True)
def help_context_url(context):
    request = context["request"]
    url_name = request.resolver_match.url_name if request.resolver_match else None
    tab = request.GET.get("tab")
    slug = resolve_context_slug(url_name, tab)
    return reverse("help:article", args=[slug])
```

Ссылка кнопки «?» вычисляется на сервере по `request.resolver_match.url_name` + `?tab=` — никаких JS-определений вкладки (надёжнее, чем парсинг location, и работает в мобильном меню).

### 6.3. Гарантии против дрейфа

| Риск | Защита |
|---|---|
| Переименуют url_name или вкладку (уже случалось: 6581047, M4 ЗM4-1 — «Запросы»/«Отчёты»; в M1–M6 добавилась вкладка matrix) | Тест `test_context_map.py`: параметризованный прогон всех правил + проверка, что **каждый slug карты существует в `load_articles()`**; проверка «все url_name из правил встречаются в urls.py проектов» — поймает переименование на CI |
| Статья контекста удалена/переименована | `resolve_context_slug` возвращает slug, а `{% url %}` на отсутствующую статью упадёт — поэтому тест-связка (см. выше) обязательна; в рантайме `HelpHomeView` и тег не делают fallback-исключений: битая карта = падение теста, не 500 у пользователя |
| Прямый заход на `/help/` без контекста (закладка, из вьювера) | `HelpHomeView` → `start` |
| Мусор в `?tab=` (ручная правка URL) | Правило не совпадёт → для `project_detail` сработает правило с `tab=None` → «Документы» — безопасный fallback |

## 8. AI-поиск (опционально, этап H5)

### 8.1. Сценарий

Обычный поиск — точный (подстрока). Он честно отдаёт пустой результат на перефразированных вопросах («как выгрузить ведомость» при тексте «экспорт перечня»). Тогда в блоке пустого результата появляется кнопка **«Спросить у ИИ»** → POST `help:ai_ask` → короткий ответ **строго по корпусу справки** + ссылки на 2–3 статьи-источника.

### 8.2. Дизайн (без новых моделей и миграций)

```
docs/help/*.md ──► build_help_index()  (help/ai.py, лениво, раз на процесс)
                   │  чанки: статья → по H2 (переиспользовать split_into_chunks,
                   │         ai_checks/domain/services.py:80)
                   │  эмбеддинги: ai_checks.adapters.embedding_factory (bge-m3)
                   └► in-memory индекс: np.array + косинус (десятки чанков —
                      pgvector/VectorBackend/БД не нужны)

HelpAiAskView ─► ai_answer(question):
                   1. embed(question), top-5 чанков (порог релевантности)
                   2. промпт: «Ты ассистент справки Stream-CAD. Отвечай ТОЛЬКО
                      по приведённым фрагментам. Если ответа нет — скажи это
                      и предложи создать обращение.»
                   3. LLMProvider.complete(...) (ai_checks/ports/llm.py:30)
                   4. Ответ + sources: [{slug, title, url}] — ссылки на статьи
```

### 8.3. Гейты и деградация

| Условие | Поведение |
|---|---|
| `AI_CHECKS_ENABLED=False` | Вьюха `HelpAiAskView` → 404 (конвенция `ai_checks/views.py:69-70`); кнопка «Спросить у ИИ» в шаблоне не рендерится (`settings.HELP_AI_ENABLED`) |
| Нет ключа эмбеддингов / провайдер недоступен | Кнопка скрыта (проверка при построении индекса), при ошибке в полёте — сообщение «ИИ временно недоступен. Создайте обращение» + та же кнопка тикета |
| Релевантность ниже порога | Ответ «В справке нет материала по этому вопросу» + CTA обращения (не выдумываем ответ) |
| Злоупотребление | Простой лимит: счётчик запросов на пользователя в cache (например, 20/сутки), 429 при превышении |

**Ограничение фиксируем:** RAG — только по `docs/help/`. Никакого доступа к документам проектов, векторам KB и пр. — это отдельный контур (вкладка «Поиск» в проекте; с M6 его `rag_answer` включает ещё и автосводку «Матрицы заданий» — `ai_checks/domain/services.py:505-540` — границу это не меняет: индекс справки H5 строится изолированно, из файлов `docs/help/`).

## 13. Граничные случаи

- **Полноэкранный вьювер** (`document_detail.html`) не наследует `base.html` (`base.html:2-4`) — кнопки «?» там нет в MVP. Справка из вьювера — через Ctrl+K палитру в перспективе (§14); сейчас допустим прямой URL.
- **Аноним** (страница логина): кнопка не рендерится — блок уже гейтится в топбаре (`_topbar.html:30`).
- **Пустой каталог справки** (каталог не создан/чист): страница `/help/` отдаёт каркас с пустым деревом и подсказкой админу, не 500 (loader возвращает пустой dict + warning).
- **Ссылка на якорь статьи, которого нет** (`/help/viewer/#нет-такого`): страница открывается с начала — стандартное поведение браузера, ничего не ломает.
- **HTMX отсутствует/отключён** (старый клиент): `Enter` в поиске → обычный GET полной страницей (`HelpSearchView` различает по `HX-Request`).
- **Компания у пользователя не определена** (клик «Создать обращение»): поведение существующее — `submit_feedback` вернёт PermissionDenied, модалка покажет ошибку (`views.py:5354-5361`) — ничего нового не требуется.
- **Одновременный доступ к статье во время релиза** (файл заменён между чтением и отдачей): чтение атомарно на уровне чтения файла целиком; худший случай — старая версия в кэше одного воркера до инвалидации.

## 14. Что сознательно не делаем

1. **Не используем `Issue` для тикетов справки** — модель обязана ссылаться на документ (`issues/models.py:19`); помощь к документам не привязана.
2. **Не делаем БД/CMS для статей в MVP** — файлы в репозитории, как согласовано; переезд в БД осмыслен только вместе с редактором и правками из UI (отдельная задача).
3. **Не дублируем «Базу знаний» проекта** — KB (`ai-kb`) — корпус для ИИ по документам проекта; справка — по интерфейсу. Разные данные, разные аудитории.
4. **Не встраиваем справку в полноэкранный вьювер** — у него собственная разметка; вынести кнопку «?» во вьювер — отдельная задача, если всплывёт.
5. **Не меняем поведение существующей модалки обратной связи** (BUG/UX/IDEA/OTHER) — только добавляем вариант «Вопрос» и префилл.
6. **Не делаем почтовые/колокольчиковые уведомления админам о вопросах** — паритет с текущим контуром feedback (админ смотрит `/feedback/`); при желании — отдельная малая задача на `Notification`.
7. **Не берём Vitro-CAD-подход** (PDF-мануалы, внешнее обучение) и не тащим видео/курсы.
8. **Не делаем per-company справку** в MVP — контент общий; изоляция по компаниям понадобится только если появятся юридически/процессно разные инструкции.
9. **Не интегрируем статьи в палитру Ctrl+K** в MVP (в перспективе — добавить `help:search` источником в `PaletteSearchView`).
