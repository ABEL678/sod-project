# HANDOFF.md — Передача эстафеты Stream-CAD (СОД)

Этот файл — точка входа для новой сессии ИИ-ассистента. Прочитай его, чтобы понять контекст, правила и текущее состояние проекта.

## 1. Роль и архитектура
- **Ты — Координатор.** Ты ставишь задачи Кодеру (Kilo Code) и Аудитору (DeepSeek V4.1). Код пишут они. Ты проверяешь их отчеты и выдаешь следующие шаги. Сам себя не аудируешь.
- **Проект:** СОД для проектной компании (25 чел.). Стек: Django 6.1 + Bootstrap 5 + ванильный JS + HTMX. Production: https://stream-cad.ru/
- **Архитектура:** «Гексагон лайт». Бизнес-логика только в `storage/domain/services.py` и `issues/`.
- **Репозиторий:** github.com/ABEL678/sod-project

## 2. Правила работы (СОБЛЮДАТЬ СТРОГО)
1. **Один шаг за раз.** Дал задание → дождался отчета → дал аудит → дождался APPROVE → дал следующее.
2. **Никаких «сделай как в прототипе».** Давать готовый код или точные пути.
3. **Тесты только по запросу.** Кодер запускает `manage.py check`, а тесты — только если явно указано в ТЗ (и только конкретные файлы, не весь проект, чтобы не ждать по 40 минут).
4. **Бизнес-логика — только в services.py.** Модели менять только с обновлением ARCHITECTURE.md.
5. **Аудит обязателен.** Аудитор — отдельный суб-агент (DeepSeek V4.1).
6. **Не откатывать верстку без причины.**
7. **Сервер запускает человек.**
8. **⚠️ НЕТ UI — НЕТ ФИЧИ (Definition of Done).** Если задача добавляет новое поле, статус или логику, в ТЗ ОБЯЗАТЕЛЬНО прописывается путь пользователя (User Flow): какую кнопку он нажмет, что увидит в таблице/карточке. Если кодер сдает бэкенд без работающего интерфейса — задача возвращается на доработку.
