## Ограничения (Архитектура и код)

### Архитектура
- **Домен чистый.** `storage/domain/` не зависит от Django views, почтовых задач и т.д.
- **Порты и адаптеры.** Всё внешнее (хранение файлов, почта, ИИ) — через интерфейсы в `ports/`.
- **Бизнес-логика — только в `domain/services.py`**. Views вызывают сервисы, а не пишут логику сами.
- **`upload_document()`** — единственная точка создания версий документа.

### Backend (Django)
- Не создавай `DocumentVersion` напрямую во views или почтовых задачах. Только через `services.upload_document()`.
- Не меняй модели из `docs/ARCHITECTURE.md` без обновления этого файла.
- Не добавляй Celery, Redis, pgvector, пока явно не попросят (см. MASTER_SPEC).

### Общее
- **Не добавляй новые зависимости** без согласования.
- **Не переписывай архитектуру** без согласования.
- **Не оставляй `print(...)`** в коде (используй `logging`).
- **Не оставляй `TODO`** без задачи в `MASTER_SPEC.md`.

## Стиль работы

### 1. План → Утверждение → Исполнение
**Всегда:**
1. **Plan Mode.** Сначала опиши план: что, зачем, какие файлы.
2. **Жди утверждения** от человека.
3. **Agent Mode.** Только после «ок» — пиши код.

### 2. Маленькие шаги
- Одна задача — один коммит.
- После каждого шага — проверка (`python manage.py makemigrations`, `migrate`, запуск сервера).

### 3. Тесты обязательны
- Для бизнес-логики (`domain/services.py`).
- Стиль — стандартный `unittest` / `pytest-django`.

### 4. Коммиты
Формат: `<type>(<scope>): <короткое описание>`
**Типы:** `feat`, `fix`, `docs`, `refactor`, `test`, `chore`.

## Три роли (координатор — аудитор — управляющий)

| Роль | Кто | Что делает |
|---|---|---|
| **Координатор** | Kilo (Code) | Ведёт подсессию, пишет код, коммитит (с разрешения человека) |
| **Аудитор** | Kilo (Суб-агент auditor, DeepSeek V4.1) | Проверяет план/код по чек-листу, выносит APPROVE / CHANGES REQUIRED |
| **Управляющий** | Человек | Задаёт правила, решает архитектурные споры |

**Правила:**
- Координатор **не** аудирует сам себя — аудит делает отдельный суб-агент.
- Аудитор **не** меняет код. Только отчёт.
- Коммит — только после `APPROVE` аудитора и с разрешения человека.
