# MASTER_SPEC.md — СОД для проектной компании

**Версия:** 1.4
**Дата:** 2026-10-30
**Статус:** Живой документ.

## 1. Цель продукта

Дать проектной компании (25 человек) порядок в файлах: актуальные версии, понятные права, быстрый поиск. Интеграция с экосистемой (ГИП-Ассистент, ВОР-билдер, Витро-трекер). Возможность продавать как SaaS (stream-cad.ru), так и On-premise (коробка).

## 2. Пользователи и роли

| Роль | Что делает | Что видит |
|---|---|---|
| **Platform Owner (суперюзер)** | Управляет компаниями, назначает админов | Список компаний. Проекты — только если компания не приватная. |
| **Администратор компании (admin)** | Управляет пользователями, проектами, правами | Всё в своей компании |
| **ГИП (gip)** | Ведет проект, утверждает документы, ставит замечания | Всё в своих проектах |
| **Разработчик (developer)** | Загружает чертежи в свои разделы, ведёт замечания | Свои разделы — запись (WIP), остальные — чтение |
| **Проверяющий (checker)** | Проверяет документы, создаёт и закрывает замечания | Только чтение файлов |
| **Нормоконтроль (normocontrol)** | Проверяет оформление, создаёт и закрывает замечания | Только чтение файлов |
| **Заказчик (customer)** | Создаёт и закрывает замечания | Только чтение файлов |
| **Смежник (contractor)** | Читает и загружает выданные разделы, создаёт замечания | Только разрешенные разделы |
| **Наблюдатель (viewer)** | Смотрит, не меняет | Только чтение |

### Этап 7.5. Файловая структура и выпуск комплектов (T8-CORE — В РАБОТЕ)
**Цель:** полноценная среда для проектировщиков.
- Иерархия папок (Folder).
- Кнопки создания проекта/раздела/папки.
- Ссылки (public_link_token).
- Массовые действия (ZIP, перемещение).
- Корзина (Trash).
- Статусы жизненного цикла (WIP, SHARED, PUBLISHED, ARCHIVED).
- **T8-CORE-ULTIMATE:** фильтрация по папке/разделу через GET, хлебные крошки, drop-зона только в таблице, ресайз панели и колонок, порядок колонок в localStorage, фильтры в шапке таблицы, счётчик выбранных, автоскролл к загруженному файлу, предупреждение при удалении папки с файлами, «Очистить корзину» только для администратора (физическое удаление через FileStorage.delete()).
- **T9-UI-V2:** стандартная таблица django-tables2 Bootstrap 5 с CheckBoxColumn, панель фильтров django-filter над таблицей, AJAX-фильтрация через HTMX, дерево папок на Bootstrap list-group с рекурсивным шаблоном, Bootstrap modal для создания/переименования папок, SortableJS для порядка колонок (localStorage), без самописного JS для таблицы и дерева.
- **T9-FIX-DND:** строки документов перетаскиваются на папки и разделы дерева; перемещение через `POST /documents/<id>/move/` и `move_document`/`move_document_to_section`; таблица обновляется через HTMX. Массовое перемещение через чекбоксы убрано.
- **T9-FIX-DND-BUG:** ID документа берётся из `data-document-id`/кастомного MIME и нормализуется до числа; Ctrl при drop — копирование через `/documents/<id>/copy/`; папки перетаскиваются с проверкой циклов через `/folders/<id>/move/`; контекстное меню папки на Bootstrap dropdown.
- **T9-FIX-DELEGATION:** единые делегированные обработчики `contextmenu`/`dragstart`/`drop` на документе; ПКМ по старым и новым папкам, ПКМ по строкам документов («Открыть», «История версий», «Скопировать ссылку», «Переместить в…», «Удалить в корзину»); drag-and-drop продолжает работать после HTMX-обновления.
- **T9-FIX-FOLDER-HTML:** у каждой папки (корневой, вложенной, проектной) единый набор `folder-row`/`data-folder-id`/`data-folder-row`/`data-folder-url`; делегированный `contextmenu` и `dragstart` ищут `.folder-row`/`[data-folder-id]`, поэтому ПКМ и перетаскивание работают независимо от расположения папки.

### Этап 10. Жизненный цикл документа и ГОСТ-роли

**Цель:** Привести систему к стандартам проектирования (WIP, Shared, Published, Archive) и ролям по ГОСТ.

**Требования:**
1. **Зоны жизненного цикла:** 4 зоны (WIP, SHARED, PUBLISHED, ARCHIVE), автоматически создаются при старте проекта.
2. **Связь статуса и зоны:** При перемещении документа в зону статус меняется автоматически.
3. **Права по зонам:** WIP — разработчики, SHARED — ГИП, PUBLISHED — админ, ARCHIVE — только чтение.
4. **ГОСТ-роли:**
   - Администратор
   - ГИП
   - Разработчик (бывший engineer)
   - Проверяющий (checker)
   - Нормоконтроль (normocontrol)
   - Заказчик (customer)
   - Смежник (contractor)
   - Наблюдатель (viewer)
5. **Матрица статусов замечаний:**
   - Новое (создал Заказчик/Проверяющий/Нормоконтроль)
   - Принято в работу (Разработчик)
   - Не принято (Проверяющий/Заказчик)
   - К обсуждению (Разработчик)
   - Выполнено (Разработчик)
   - Закрыто (Проверяющий/Заказчик/Нормоконтроль)
   - Аннулировано (Проверяющий/Заказчик/Нормоконтроль)

**Критерий готовности:** проект создается с 4 зонами, документы перемещаются по зонам со сменой статуса, роли соответствуют ГОСТ, замечания меняют статусы по матрице.

### Этап 11. ГОСТ-роли и матрица статусов замечаний (T11-ROLES)
**Цель:** привести роли и жизненный цикл замечаний к ГОСТ.

**Требования:**
1. **ГОСТ-роли в `UserProfile.role`:** admin, gip, developer (бывший engineer), checker, normocontrol, customer, contractor, viewer.
2. **Права на файлы:** developer и contractor пишут только в allowed_sections (WIP); checker, normocontrol, customer, viewer — только чтение.
3. **Создание замечаний:** developer, checker, normocontrol, customer, contractor, gip, admin; viewer — запрещено.
4. **Статусы Issue:** NEW, IN_PROGRESS, REJECTED, DISCUSSION, DONE, CLOSED, CANCELLED. Поля `author`, `assignee`, `closed_at`, `closed_by`.
5. **Матрица переходов:**
   - developer — IN_PROGRESS, DISCUSSION, DONE;
   - checker / customer / normocontrol — NEW (при создании), REJECTED, CLOSED, CANCELLED;
   - gip / admin — любые статусы;
   - contractor / viewer — не меняют статус.
6. **Сервис `update_issue_status()`** проверяет матрицу, пишет `closed_at`/`closed_by` при CLOSED/CANCELLED.
7. **UI:** ГОСТ-названия ролей, цветной бейдж статуса, кнопки статусов только по матрице.
8. **Data-миграция:** `engineer` → `developer` для `UserProfile` и `ProjectMembership`; статусы Issue `open/in_progress/closed` → `NEW/IN_PROGRESS/CLOSED`.

**Критерий готовности:** роли соответствуют ГОСТ, замечания меняют статусы только по матрице, 233+ теста зелёные.
