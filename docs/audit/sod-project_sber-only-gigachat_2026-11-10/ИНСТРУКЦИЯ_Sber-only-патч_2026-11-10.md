## 1. Что делает патч

### 1.1. OrcaRouter удалён полностью
- `ai_checks/adapters/llm_http.py` — удалён класс `HttpLLMProvider` (шлюз `https://api.orcarouter.ai/v1`, deepseek/*, z-ai/*). Фабрика `get_llm_provider()` теперь всегда отдаёт **GigaChatProvider** (Сбер), а без ключа `AI_GIGACHAT_AUTH_KEY` — заглушку `StubLLMProvider` (контур не падает, ответ синтезируется из найденных фрагментов).
- `sod_core/settings.py` — настройки `AI_LLM_API_KEY`, `AI_LLM_BASE_URL`, `AI_LLM_MODEL`, `AI_LLM_TIMEOUT`, `AI_LLM_PROVIDER` удалены целиком.
- `.env.example`, `.env.production.example` — OrcaRouter-переменные заменены на GigaChat-блок.
- Заодно исправлен дефект: двойной вызов `response.raise_for_status()` в `GigaChatProvider.complete()`.

### 1.2. Селектор моделей в UI — только GigaChat
`AI_AVAILABLE_MODELS` теперь:
- `GigaChat-2-Max` — **проверен владельцем** (связные ответы с цифрами), стоит первым и является дефолтом `AI_GIGACHAT_MODEL`;
- `GigaChat-3-Pro` — оставлен по вашему выбору (**проверьте доступность на вашем тарифе** — в публичной freemium-таблице его нет; если недоступен, просто удалите строку из списка);
- `GigaChat-3-Ultra` — закомментирован (доступен только через отдельный контур `api.giga.chat`, раскомментируйте при необходимости).

Серверная валидация `ai_checks/views.py::_selected_model` читает этот же список, поэтому прямые POST с чужими кодами моделей отклоняются — UI и API закрыты одновременно.

### 1.3. Выбор эмбеддинг-модели (Сбер)
- **Новый файл `ai_checks/adapters/embedding_gigachat.py`**: класс `GigaChatEmbedding` — OAuth-токен общий с LLM (Authorization Key → токен с кэшем 25 мин), запрос `POST {AI_GIGACHAT_API_BASE_URL}/embeddings` с `{"model": ..., "input": [...]}`, разбиение на батчи по `AI_EMBEDDING_BATCH_SIZE` (8), восстановление порядка ответа по полю `index`, retry ×2, при 401 — сброс и перезапрос токена.
- **Fail-fast** (как принято в проекте): без ключа — `RuntimeError` с инструкцией; если фактическая размерность вектора ≠ `AI_EMBEDDING_DIM` — `RuntimeError` с подсказкой (индекс не портится).
- **Фабрика `get_embedding_service()`**: `AI_EMBEDDING_PROVIDER='gigachat'` (по умолчанию, облако Сбера) или `'onnx'` (офлайн-фолбэк bge-m3, старый `BgeM3OnnxEmbedding` сохранён и работает).
- Три точки в `ai_checks/domain/services.py` (`index_document`, `index_project_document`, `rag_answer`) переключены с прямого `BgeM3OnnxEmbedding()` на фабрику.
- Настройки: `AI_EMBEDDING_MODEL` (варианты: `Embeddings`, `Embeddings-2`, `Embeddings-3B-2025-09`, `EmbeddingsGigaR` — подтверждены официальной таблицей моделей Сбера), `AI_EMBEDDING_DIM=1024`, `AI_EMBEDDING_BATCH_SIZE=8`, `AI_EMBEDDING_TIMEOUT=60`.
- **Дефолт — `Embeddings`** (базовая модель, «доступная по умолчанию» по документации Сбера). UI-селектора для эмбеддингов сознательно **нет**: векторы разных моделей несравнимы, выбор на уровне пользователя привёл бы к смешиванию в индексе. Выбор — только через `.env` + переиндексация.

## 4. ⚠️ Переиндексация — ОБЯЗАТЕЛЬНЫЙ шаг

Старый векторный индекс построен на **bge-m3**; векторы GigaChat в другом пространстве — **смешивать нельзя** (RAG-поиск выдаст мусор). После патча и настройки `.env`:

1. **Документы проекта:** UI → «Переиндексировать проект» (пересчитает `ProjectDocumentChunk`).
2. **База знаний:** переиндексировать документы (`InternalChunk`) — через перезагрузку документов в разделе «База знаний».
3. **Проверка:** задать в RAG вопрос по известному документу — источники должны быть релевантны.

Если база пустая или тестовая — просто продолжайте работу, индексация пойдёт по GigaChat с нуля.

На проде после патча перезапустите воркер Celery (индексация идёт в задачах) и gunicorn.

## 5. Проверка размерности выбранной модели (один раз, до переиндексации)

Размерность моделей эмбеддингов GigaChat в открытой таблице моделей **не публикуется**. Колонки pgvector сейчас `vector(1024)`, дефолт `Embeddings` рассчитан на 1024. Проверьте фактически:

```bash
# 1. Получить OAuth-токен (Authorization Key — одна строка):
TOKEN=$(curl -s https://ngw.devices.sberbank.ru:9443/api/v2/oauth \
  -H "Authorization: Bearer <AI_GIGACHAT_AUTH_KEY>" \
  -H "RqUID: $(uuidgen)" -H "Content-Type: application/x-www-form-urlencoded" \
  --data 'scope=GIGACHAT_API_PERS' | python3 -c "import json,sys; print(json.load(sys.stdin)['access_token'])")

# 2. Запросить вектор и напечатать размерность:
curl -s https://api.giga.chat/v1/embeddings \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"model":"Embeddings","input":["тест"]}' \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(len(d['data'][0]['embedding']))"
```

- Если выведет **1024** — ничего делать не нужно (миграций в патче нет).
- Если **другое число** — либо выберите другую модель из списка, либо (осознанный путь) добавьте миграцию: очистить чанки → удалить HNSW-индекс → `ALTER COLUMN embedding TYPE vector(N)` (для обеих таблиц `InternalChunk` и `ProjectDocumentChunk`) → пересоздать индекс → задать `AI_EMBEDDING_DIM=N` → полная переиндексация. Адаптер не даст записать вектор не той размерности — это защита, а не помеха.

## 7. Известные ограничения

- **GigaChat-3-Pro** — проверьте на своём тарифе; недоступную модель уберите из `AI_AVAILABLE_MODELS` (одна строка в `sod_core/settings.py`).
- **GigaChat-3-Ultra** — закомментирован: требует контур `api.giga.chat` (базовый URL тот же, но тариф отдельный).
- **OAuth scope** — как и раньше, `GIGACHAT_API_PERS` (личный тариф). Для корпоративного ключа смените scope в `GigaChatProvider.get_token()`.
- Заглушка без ключа (`StubLLMProvider`) работает как раньше — контур не блокируется, но синтез без LLM.
- Исторические доки `docs/audit/**` упоминают OrcaRouter — это осознанно (снимки состояния на дату аудита).
